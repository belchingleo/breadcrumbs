# Breadcrumbs · 思路

> 《糖果屋》中汉赛尔和格莱特被丢进森林，沿路撒下面包屑，希望天亮后能原路走回去。

<img width="1774" height="887" alt="image" src="https://github.com/user-attachments/assets/4e78f9e0-8189-41cc-b177-af680dbb433c" />


如果你习惯使用Codex或者Claude code进行文字创作或者发散性讨论，
比如选题讨论、论文写作、头脑风暴等，在多轮场对话之后，有没有发现一种无意识的注意力漂移情况。
之所以无意识，是因为在密集的多轮次对话中，相近轮次话题的偏移并不明显，是很自然的“你来我往”的承接。
而且对话是一条线性滚动流。**它记录的是「说过什么」，不是「我怎么走的」**：
没有分叉的概念，没法把第 8 轮和第 40 轮并排比较，回退等于往上滚动然后失去下文。
但当你有机会回头复盘的时候，你会发现**终点和起点并不在一条线上**。

**这种偏移对发散性思考并不是坏事，甚至可能是好事**。但是我们需要一个工具来复盘思路，
在哪里走对了，又或是从哪里开始走偏了。
所以这个skill就试图**帮你找到对话中的面包屑**，它能帮你复盘一段较长的 **Claude Code** 或 **Codex**
对话：把你自己输入的 prompt 重建成可返回的原话锚点与讨论路径，
核实每条“岔路”留下了什么、怎样影响主问题、哪些仍然开放，并生成一份本地 HTML 复盘稿。

这个问题其实在浏览器里做检索时它就存在：检索链越拉越长，深入到某一步，
你甚至忘了自己最初要查什么。在社交媒体检索和刷短视频中感受可能更加明显，注意力经常被某些信息打断。
但浏览器至少还留着标签页和历史记录作为某种空间线索，能回头对着看。
这个skill受到浏览器中Breadcrumbs设计的启发，它要解决的不是「AI 说了什么」，而是

> 我是怎么走到终点的？哪些问题提了但没收束？现在能从哪句原话重新进入工作？

## 在线演示

打开 [完全虚构的交互演示](https://belchingleo.github.io/breadcrumbs/)：
点击来路图定位思路，打开当时原话，并为未收束的问题复制返回提示词。
演示使用虚构的“社区共享花园策划”对话，不包含任何真实用户数据。

## 这不是什么

- **不是对话摘要。** 摘要压缩「说了什么」；Breadcrumbs 保存「思路怎样移动、
  哪些没兑现、从哪句原话能回去」。
- **不是注意力纠偏。** 它不评判你「跑偏」。注意力转移被当作可能产生新问题的
  材料，不是需要纠正的错误。
- **不做注意力提醒。** 只在你主动要求复盘时运行。

> 希望通过复盘用户输入prompt，将注意力的漂移转换成生产力。

## 适用对象

- **研究者、论文写作者**：长线思考跨天跨周，一条被搁置的追问过两天就想不起来了
- **编辑、记者**：改稿过程中反复调整切口，需要知道「这版和最初想写的还是同一篇吗」
- **产品、策略工作者**：开放式讨论里岔路多，事后要交代哪条岔路真带回了东西

## 什么样的会话跑出来才有东西

| 会话类型 | 典型说法 | 跑出来是什么 |
|---|---|---|
| **意义建构型** | 「这个结构对吗」「我是不是把前提搞错了」 | 多条追问线交错，分岔密集——**这是它最有用的场合** |
| **执行型** | 「照这个写第三节」「把格式改一下」 | 一条长主干，少量事务性支线，可说的不多 |

目的性强的vibe coding、翻译，对话轮次过少（少于 15 轮左右）不建议使用。

## 运行前提

**Python 3 标准库** 不需要 numpy、scikit-learn、虚拟环境或联网。
相似度用纯 Python 的字符 n-gram TF-IDF 实现——选择零依赖是为了让非工程背景的
使用者能直接用。

读取 Codex 任务时另需本机 `codex` 命令（通过官方 App Server 读取，
不解析不稳定的原始 transcript 格式）。

## 安装

```bash
git clone https://github.com/belchingleo/breadcrumbs.git
cd breadcrumbs
python3 scripts/install.py --target claude   # 或 --target codex / --target both
```

安装后在 Claude Code 或 Codex 中直接说「复盘这次对话」或 `/crumbs` 即可。

## 工作方式

脚本负责便宜、可复现的结构；模型负责必须读上下文才能完成的语义核实。

```
1  定位会话        脚本   列出本机会话，或 --last
2  结构分析        脚本   抽取真人 prompt → 相似度 → 最近邻链接 → 候选思路（0 token）
3  批量回读        模型   一次取回各思路起点前与末次后的必要回复，填写语义标注
4  校验并渲染      脚本   身份不匹配则拒绝出图 → 单文件 HTML
5  重新进入工作    页面   来路图 / 复盘总览 / 思路复盘 / 原话与完整结构
```

**AI 回复不全量进入结构分析**，只在需要判断「这条思路由谁引出、留下了什么、
是否收束」时回读。默认把所有必要位置合并为一次工具调用，并折叠每条思路的
中段输入；需要更多证据时才单点补取。这同时控制 token、隐私与幻觉风险。

生成的复盘稿分为三层：

1. **来路图**：显示从哪里开始、在哪里分叉、后来回到哪里；
2. **复盘总览**：呈现最初在问、最后停在、未尽事宜、这次改变了什么和建议继续；
3. **思路复盘**：逐条核实产出、对原问题的作用、收束状态，并可打开原话或复制
   返回提示词。完整讨论结构保留为第二级证据视图。

## 可信度设计

这个工具的全部价值建立在「这条路确实对应我当时的问题」之上，所以：

- 每份分析带 `analysis_id`、会话指纹与每条思路的内容签名；
  **标注与分析不匹配时拒绝渲染**，而不是静默出一张错位但漂亮的图。
- 声称「仍然开放」属于否定性断言，**必须附回读证据**才能通过校验。
- 页面中语义名称由模型核实过才显示为实心；路径连接始终保留虚线，
  因为算法画出的每一次转向并未被逐段确认。
- 历史语料不足时进入降级模式，页面显式标注低可信度，不伪装成正常结果。
- 用户可见层不出现「线 3」「第 18 轮」这类工程标识；记录号只留在诊断区。

## 隐私

全部在本地完成，不联网，不上传。生成的 HTML 内嵌你的完整 prompt 原文，
**分享前请自行确认内容**。仓库的 `.gitignore` 默认排除运行产物
（`analysis*.json`、`annotations.json`、`*.html`）。

## 测试

```bash
python3 tests/test_regression.py
```

这些是**正确性回归测试**——错位必须被拒绝、注入必须被转义、静默丢弃不许发生。
刻意不包含「什么算一条新线」这类语义评测：现阶段把启发式偏好固化成基准，
只会给尚未稳定的判断上锁。

## 已知限制

- 仅适配 Claude Code JSONL 与 Codex 本地任务；claude.ai 导出格式尚未接入。
- 字符 n-gram TF-IDF 擅长词汇重叠，**不理解同义改写**——算法只提供候选结构，
  最终划分需要模型读原文后校订。
- 谈论「我们该怎么协作」这类元轮次，用词远离正题，容易被切成独立思路。
- 当前一次只复盘一个会话。跨会话内容签名已预留，但「同一主题在多个窗口中
  怎样延续、A 会话的未尽事宜是否在 C 会话解决」尚未实现。
- 目前只在少量真实会话上验证过，分线结果对实现细节仍然敏感。
